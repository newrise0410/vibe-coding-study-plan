# 바이브코딩 3주 스터디 — 홈페이지부터 결제까지

15일 뒤면 **로그인부터 상품 등록, 이미지 업로드, 카드 결제까지 작동하는 웹사이트** 하나가 인터넷에 올라간다.
사실 AI에 지시만 잘 내려도 여기까지는 어떻게든 만든다.

하지만 이 스터디가 진짜 노리는 지점은 그다음이다.
**AI가 모든 걸 대신 해줘도 그 속에서 무슨 일이 벌어졌는지 똑똑히 아는 상태.**

---

## 이 스터디의 전제

솔직히 짚고 넘어가자. **웬만한 구현은 AI가 다 처리해준다.**
"쇼핑몰 하나 만들어줘"라는 한마디에 그럴싸한 결과물이 뚝딱 나온다. 이미 검증된 사실이니 굳이 여기서 다시 배울 이유가 없다.

진짜 문제는 그 뒤에 터진다.

- 내 컴퓨터에선 멀쩡한데 배포만 하면 DB 연결이 끊긴다. 어디를 건드려야 할지 깜깜하다.
- 결제 완료 알림은 왔는데 DB에 주문 데이터가 빠져 있다. 어디서 꼬였는지 감조차 안 잡힌다.
- API 키의 올바른 위치를 몰라 프론트엔드 코드에 그대로 노출한다.
- 브라우저에서 결제 금액을 직접 넘기는 행위가 왜 치명적인지 깨닫지 못한다.

**마지막 문제는 실제 금전 손실로 직결된다.** AI는 시키는 코드를 작성할 뿐, 내 지식의 구멍까지 짚어주지 않는다.

결국 이 스터디는 코드를 직접 타이핑하는 자리가 아니다. **AI가 만들어낸 코드를 해부하는 과정이다.**

---

## 퀘스트는 이렇게 생겼다

매일 하나. 5단계를 지난다.

| 단계 | 하는 일 |
|---|---|
| **1. 원리 먼저** | 원래 이건 이런 구조로 돌아간다 (5~10분 분량) |
| **2. 시켜보기** | AI에게 요청한다. 여기는 빨리 지나간다 |
| **3. 해부하기** | 결과물에서 그 구조가 어디 있는지 **직접 찾아 지목한다** |
| **4. 부숴보기** | 일부러 망가뜨리고 무엇이 무너지는지 관찰 → 되돌린다 |
| **5. 스스로 답하기** | 확인 질문 3개 |

3단계 **해부하기** 과정은 Orca가 든든하게 받쳐준다.
diff 뷰어가 거터 영역에 **AI가 작성한 줄을 명확히 구분해 표시**한다(Attribution). 내가 쓴 코드와 에이전트가 쓴 코드가 갈라지므로 어느 대목부터 읽어야 할지 바로 감이 잡힌다.

**인증 기준은 "만들어냈다"가 아닌 "찾아냈다 / 관찰했다"이다.**
단순히 완성 화면 스크린샷 제출로는 인증할 수 없다. AI에게 맡기기만 해서는 결코 답할 수 없는 질문을 던지기 때문이다.

핵심은 4단계 **부숴보기**다.
특정 기능의 본질을 파악하는 가장 빠른 길은 그 요소를 직접 제거해보는 일이다.
이 작업을 안전하게 수행하도록 지원하는 도구가 바로 **Orca의 워크트리**다. 마음껏 망가뜨린 뒤 해당 워크트리만 통째로 버리면 그만이다.
`<script>` 태그 위치를 슬쩍 바꾸거나, DB 접속 IP를 막아버리거나, 브라우저상에서 결제 금액을 변조해보자. 매번 각기 다른 형태로 시스템이 틀어진다. 그 오류의 결 차이를 파악하는 행위가 곧 구조를 이해하는 열쇠다.

## 만드는 것

**공통 프로젝트: 동네 카페 `들꽃` 온라인 스토어**

```
방문자   상품 목록 → 상품 상세 → 로그인 → 주문 → 결제
관리자   로그인 → 상품 등록(이미지 업로드) → 주문 목록 확인
```

규모는 작아도 **진짜 서비스에 들어가는 필수 요소가 빠짐없이 집약되어 있다.** 사용자 화면부터 API, DB, 파일 저장소, 인증 시스템, 결제 모듈, 최종 배포까지 모두 포함한다.

**개인 프로젝트 확장**: 판매 품목은 취향껏 바꾼다. 원두 대신 개인 그림 작품이나 직접 만든 굿즈, 원데이 클래스 예약 등 무엇이든 상관없다.
소프트웨어 뼈대는 동일하고 다루는 아이템만 달라지므로 스터디원끼리 서로 조언을 주고받기도 쉽다. 완성품은 온전히 나만의 포트폴리오가 된다.

## 기술 스택

| 역할 | 도구 | 왜 |
|---|---|---|
| 화면 + 서버 | **Next.js** | 프론트와 API를 한 프로젝트에서. 서버를 따로 안 띄워도 됨 |
| DB | **MongoDB Atlas** | 무료 티어, JSON 형태라 첫 DB로 진입장벽 낮음 |
| 이미지 저장 | **Cloudinary** | 무료 티어, 업로드·최적화·CDN이 한 번에 |
| 로그인 | **Auth.js (NextAuth)** | 구글 로그인. 비밀번호를 직접 다루지 않아도 됨 |
| 결제 | **포트원 + KG이니시스** | 포트원이 이니시스를 중계. 테스트 결제까지 계약 없이 가능 |
| 배포 | **Vercel** | GitHub 연결 후 푸시하면 자동 배포 |
| 작업 환경 | **Orca** | AI 에이전트를 돌리는 IDE. **AI가 쓴 줄을 표시해준다** |
| AI 에이전트 | **각자 선택** | Orca는 에이전트를 안 준다. 쓰던 걸 가져온다 |
| 관찰 | **브라우저 개발자 도구 (F12)** | 사실상 이 스터디의 주력 도구 |

세부 가이드 및 계정 설정 절차는 `resources/stack.md` 파일에서 다룬다.

> **결제 연동 유의 사항**: KG이니시스 서비스를 이용해 **실제 결제금을 수금하려 할 경우** 사업자등록 및 계약 절차가 필수다.
> 본 스터디에서는 **포트원 테스트 채널로 이니시스 결제창을 띄우고 승인부터 검증, 웹훅 전 과정을 실습 형태로 진행**한다.
> 여기서 익히는 동작 메커니즘은 실무 결제와 동일하다. 훗날 실제 계약 후 변경할 항목은 채널 키와 가맹점 정보가 전부다. (`resources/payment-inicis.md`)

## 운영 방식

- **주 5일 × 3주 = 15일**. 매일 퀘스트 하나
- 하루 **1~1.5시간**. 1주차는 가볍지만 2~3주차는 학습밀도가 꽤 높다
- 매일 아침 `#퀘스트` 채널에 그날 수행할 작업 목록이 올라간다
- 미션을 마치면 정해진 서식에 맞춰 `#인증` 채널에 기록을 남긴다
- **15분 룰 준수**: 막히는 구간이 15분을 넘기면 지체 없이 `#질문` 채널에 조력을 요청한다. 혼자 끙끙 앓다 중도 포기하는 상황이야말로 이 스터디에서 경계해야 할 유일한 실패다

### 인증 포맷

```
[Day 7] 완료
■ 해부: (찾아낸 것 — 파일명과 줄 번호까지)
■ 부숴보기: 무엇을 망가뜨렸더니 → 무엇이 어떻게 됐다
■ 답: (스스로 답하기 3문항)
■ 막혔던 것: 한 줄 (없으면 '없음')
```

`해부`와 `부숴보기` 항목이 핵심이다. 이 영역이 비어 있으면 AI에게 맡기기만 한 것으로 간주해 반려한다.
