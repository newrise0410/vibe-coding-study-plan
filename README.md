# 바이브코딩 3주 스터디 — 홈페이지부터 결제까지

15일 뒤에 **로그인하고, 상품을 등록하고, 이미지를 올리고, 카드로 결제되는 사이트**가 인터넷에 있다.
그건 사실 AI만 잘 시켜도 어느 정도 된다.

이 스터디가 진짜로 노리는 건 그다음이다.
**AI가 알아서 다 해줘도, 그 안에서 무슨 일이 일어난 건지 아는 것.**

---

## 이 스터디의 전제

솔직하게 말하고 시작한다. **웬만한 건 AI가 알아서 해준다.**
"쇼핑몰 만들어줘"라고 하면 그럴듯한 게 나온다. 그건 이미 확인된 사실이라 배울 게 없다.

문제는 그다음이다.

- 로컬에선 되는데 배포하면 DB 연결이 안 된다. 어디를 봐야 할지 모른다
- 결제가 됐다는데 주문이 DB에 안 들어갔다. 어디서 끊긴 건지 모른다
- API 키를 어디에 둬야 하는지 모른 채 프론트 코드에 박아둔다
- 결제 금액을 브라우저에서 보내고 있다는 게 왜 위험한지 모른다

**마지막 항목은 실제로 돈이 새는 문제다.** 그리고 AI는 시키는 대로 만들어줄 뿐, 내가 뭘 모르는지는 알려주지 않는다.

그래서 이 스터디는 코드를 짜는 스터디가 아니라 **AI가 짜준 코드를 해부하는 스터디**다.

---

## 퀘스트는 이렇게 생겼다

매일 하나. 5단계를 지난다.

| 단계 | 하는 일 |
|---|---|
| **1. 원리 먼저** | 원래 이건 이런 구조로 돌아간다 (5~10분 분량) |
| **2. 시켜보기** | AI에게 요청한다. 여기는 빨리 지나간다 |
| **3. 해부하기** | 결과물에서 그 구조가 어디 있는지 **직접 찾아 지목한다** |
| **4. 부숴보기** | 일부러 망가뜨리고 무엇이 무너지는지 관찰 → 되돌린다 |
| **5. 스스로 답하기** | 확인 질문 3개 |

**인증은 "만들었다"가 아니라 "찾아냈다 / 관찰했다"로 받는다.**
결과 스크린샷만으로는 통과가 안 된다. AI에게 시키기만 해서는 답할 수 없는 걸 묻는다.

가장 중요한 건 4단계 **부숴보기**다.
무언가가 무슨 일을 하는지 가장 빨리 아는 방법은 그걸 없애보는 것이다.
`<script>` 위치를 옮기면, DB 접속 IP 제한을 걸면, 결제 금액을 브라우저에서 조작하면 — 각각 다른 방식으로 망가진다. 그 차이가 곧 구조다.

주말은 밀린 걸 따라잡는 날이다. 여유 있으면 각 주말 확장 미션을 한다.

## 만드는 것

**공통 프로젝트: 동네 카페 `들꽃` 온라인 스토어**

```
방문자   상품 목록 → 상품 상세 → 로그인 → 주문 → 결제
관리자   로그인 → 상품 등록(이미지 업로드) → 주문 목록 확인
```

작지만 **실제 서비스가 가진 조각이 전부 들어있다.** 화면, API, DB, 파일 저장소, 인증, 결제, 배포.

**개인 확장**: 파는 물건은 각자 바꾼다. 원두 대신 내 그림, 내 굿즈, 클래스 예약, 뭐든.
코드 구조는 같고 도메인만 다르니 서로 도와줄 수 있고 결과물은 내 것이 된다.

## 기술 스택

| 역할 | 도구 | 왜 |
|---|---|---|
| 화면 + 서버 | **Next.js** | 프론트와 API를 한 프로젝트에서. 서버를 따로 안 띄워도 됨 |
| DB | **MongoDB Atlas** | 무료 티어, JSON 형태라 첫 DB로 진입장벽 낮음 |
| 이미지 저장 | **Cloudinary** | 무료 티어, 업로드·최적화·CDN이 한 번에 |
| 로그인 | **Auth.js (NextAuth)** | 구글 로그인. 비밀번호를 직접 다루지 않아도 됨 |
| 결제 | **포트원 + KG이니시스** | 포트원이 이니시스를 중계. 테스트 결제까지 계약 없이 가능 |
| 배포 | **Vercel** | GitHub 연결 후 푸시하면 자동 배포 |
| 편집 | **Cursor** | VS Code + AI |
| 관찰 | **브라우저 개발자 도구 (F12)** | 사실상 이 스터디의 주력 도구 |

상세 설명과 계정 준비는 `resources/stack.md`.

> **결제에 대해 미리 알아둘 것**: KG이니시스로 **실제 돈을 받으려면** 사업자등록과 상점 계약이 필요하다.
> 이 스터디에서는 **포트원 테스트 채널로 이니시스 결제창을 띄우고 승인·검증·웹훅까지 전 과정을 실습**한다.
> 배우는 구조는 실거래와 동일하고 실계약 시 바꾸는 건 채널 키와 상점 정보뿐이다. (`resources/payment-inicis.md`)

## 운영 방식

- **주 5일 × 3주 = 15일**. 매일 퀘스트 하나
- 하루 **1~1.5시간**. 1주차는 짧고 2~3주차가 무겁다
- 매일 오전 `#퀘스트` 채널에 그날 퀘스트가 올라감
- 완료하면 `#인증` 채널에 포맷대로
- **15분 룰**: 15분 넘게 막히면 무조건 `#질문`에 던진다. 혼자 끙끙대다 조용히 사라지는 게 이 스터디의 유일한 실패다

### 인증 포맷

```
[Day 7] 완료
■ 해부: (찾아낸 것 — 파일명과 줄 번호까지)
■ 부숴보기: 무엇을 망가뜨렸더니 → 무엇이 어떻게 됐다
■ 답: (스스로 답하기 3문항)
■ 막혔던 것: 한 줄 (없으면 '없음')
```

`해부`와 `부숴보기`가 핵심이다. 여기가 비면 AI에게 시키기만 한 거라 되돌려보낸다.
