# Day별 촬영 가이드

운영 웹을 만들면서 찍을 것. 만드는 내내 이 문서를 옆에 띄워둔다.

핵심은 이거다. **대부분의 화면은 한 번 지나가면 다시 못 본다.** 클러스터는 한 번만 만들고,
`create-next-app` 선택지는 프로젝트당 한 번 뜨고, Vercel Import 화면은 연결하면 끝이다.
찍을 타이밍을 놓치면 계정을 새로 파야 한다.

---

## 0. 촬영 원칙

**키를 가려라.** 이 작업에서 가장 위험한 부분이다. Atlas 연결 문자열, Cloudinary Secret,
구글 OAuth Secret이 그대로 찍힌다. 커리큘럼 Day 14가 다루는 그 사고를 운영자가 먼저 낼 수 있다.

- 스샷 찍고 **바로** 모자이크. "나중에"는 없다
- 가려도 실수했다 싶으면 **그 키는 재발급한다.** 지우는 걸로는 부족하다
- 가장 안전한 건 **교보재용 더미 계정**을 따로 파서 찍는 것

**기타**

- 브라우저 창 너비를 1280px 정도로 고정한다. 스샷 크기가 들쭉날쭉하면 읽기 나쁘다
- 에러 메시지는 **전문이 보이게** 찍는다. 잘린 에러는 검색이 안 된다
- 파일명은 `day07-atlas-connect.png`처럼. 나중에 `#공지`에 붙일 때 찾기 쉽다
- 한글 OS/영문 OS가 다르게 보이는 화면은 둘 다 있으면 좋다 (참가자 OS가 섞인다)

**표기**

- 📸 = 지금 아니면 다시 못 찍는다
- 🔁 = 언제든 재현 가능
- 💥 = 일부러 고장 내서 찍는다. **이게 가장 값진 교보재다**

## 계정 만들기 (Day 0 대비)

참가자가 첫날을 통째로 날리는 지점. `curriculum/day-00-setup.md`의 "막히면" 표가 전부 여기서 나온다.

📸 **Orca** — 다운로드 페이지에서 내 OS 빌드를 고르는 화면, 그리고 첫 실행 시
   **홈 디렉토리 접근 권한**을 묻는 화면
📸 **에이전트 콤보박스** — 워크트리 터미널 위에서 에이전트를 고르는 화면.
   Orca 는 에이전트를 주지 않으므로 참가자가 뭘 골라야 하는지 이 한 장이 설명한다
💥 **Windows "PC를 보호했습니다" 경고** — `추가 정보` → `실행` 누르기 전 화면.
   매 기수 몇 명씩 여기서 멈춘다
💥 **Mac "확인되지 않은 개발자"** — 시스템 설정 경로까지

📸 **Vercel 가입 화면** — **"Continue with GitHub" 버튼에 표시**를 해둔다.
   `operator-guide.md`가 "여기서 제일 많이 실수한다"고 꼽은 곳이다. 이메일 가입하면 배포 연동이 꼬인다

📸 **Atlas 클러스터 생성** — 클러스터당 한 번뿐이다. 4장 필요하다
1. `Create` → **M0 (Free)** 선택 화면 (유료 티어와 나란히 보이게)
2. 지역 선택 (`Seoul`)
3. **Database Access** 사용자 생성 — 비밀번호는 다시 못 본다는 경고까지
4. **Network Access** → `0.0.0.0/0` 입력 화면

📸 **Cloudinary Dashboard** — `Cloud name` / `API Key` / `API Secret` 위치에 화살표.
   **값은 전부 가린다.** 위치만 알려주면 된다

📸 **포트원** — 상점 생성 → 결제 연동 → 테스트 채널 추가 → PG사 `KG이니시스` 선택.
   콘솔 UI가 자주 바뀌니 **날짜를 스샷에 같이 남긴다.** 다음 기수엔 안 맞을 수 있다

## Day 3 — 첫 배포

전 기수 통틀어 가장 많이 터지는 문제가 여기 있다.

📸 Vercel `Add New` → `Project` → 저장소 `Import` 화면 (프로젝트당 한 번)
📸 빌드 로그가 도는 화면과 **성공 직후 주소가 뜬 화면**
🔁 Source Control에서 커밋 → 푸시 → 1분 뒤 배포 주소가 바뀌어 있는 흐름

💥 **대소문자 사고** — 이 스터디 최대 병목이다. 반드시 재현해서 찍는다
```
style.css → Style.css 로 바꿔 푸시
→ 내 컴퓨터: 멀쩡
→ 배포 사이트: 깨짐 + Network 탭 404
```
   **두 화면을 나란히** 찍어야 교보재가 된다. 찍고 나서 되돌린다

💥 viewport 메타 태그를 지우고 **진짜 핸드폰**으로 접속한 화면.
   F12 반응형 모드는 이 차이가 안 보인다. 폰으로 찍어야 한다

## Day 8–9 — 검증과 업로드

💥 **콘솔에서 `fetch`로 폼을 우회하는 화면** — 이 스터디의 사고방식 자체다
```
폼에 min="0"을 걸어둔 화면
→ 콘솔에서 price: -50000 을 직접 전송
→ 201이 오고 Atlas에 음수가 저장된 화면
```
   **세 장을 한 세트로.** Day 13 결제 금액 조작의 예고편이다

📸 업로드 3단계 요청의 **크기 비교** (Network 탭) — 큰 파일이 우리 서버를 안 거친다는 게 숫자로 보인다
```
/api/upload/sign        작다
api.cloudinary.com/...  크다  ← 실제 파일
/api/submissions        작다  ← URL만
```

💥 **`NEXT_PUBLIC_` 노출 실험** — `operator-guide.md`가 "인상이 가장 강한 실험 중 하나"로 꼽은 것
```
NEXT_PUBLIC_TEST_SECRET=이건비밀이었다
→ Sources 탭 Ctrl+Shift+F 로 검색 → 그대로 나오는 화면
```
   **검색 결과가 하이라이트된 상태**로 찍는다. 이 한 장이 Day 14를 절반 설명한다

## Day 10 — 로그인 (최대 병목)

`operator-guide.md`: "구글 콘솔 UI가 복잡하다. 스샷 가이드를 미리 만들어두면 질문이 확 준다."
가장 공들여 찍을 구간이다.

📸 구글 클라우드 콘솔 — 5장이 필요하다
1. 프로젝트 생성
2. `OAuth 동의 화면` 설정 (외부 / 앱 이름 / 이메일)
3. `사용자 인증 정보` → `OAuth 클라이언트 ID` → 웹 애플리케이션
4. **승인된 리디렉션 URI 입력 화면** — localhost와 배포 주소 **둘 다** 들어간 상태
5. 클라이언트 ID / Secret 발급 화면 (**값 가리기**)

💥 **`redirect_uri_mismatch`** — 최대 병목의 실물. 리디렉션 URI를 하나만 등록하고
   다른 쪽에서 로그인을 시도해 에러 화면을 찍는다. **끝 슬래시까지 정확해야 한다**는 걸 같이 보여준다

📸 Application 탭 → Cookies → 세션 쿠키의 `HttpOnly` 체크 표시
🔁 콘솔에 `document.cookie` 쳤을 때 세션 토큰이 **안 나오는** 화면

💥 **권한 우회** — 로그아웃 상태에서 콘솔로 관리자 API 직접 호출
```
401이 오는 화면  = 방어 성공
201이 오는 화면  = 뚫린 것
```
   운영자 본인 앱에서 한 번 뚫려보는 게 가장 좋은 교보재다. 뚫렸으면 그것도 찍어둔다

## Day 14–15 — 점검과 측정

📸 Sources `Ctrl+Shift+F`로 `mongodb+srv`, `secret` 검색 → **아무것도 안 나오는 정상 화면**
📸 (있다면) 실제로 뭔가 나온 사고 화면 — 이게 진짜 교보재다
📸 Vercel → Logs에서 실제 요청 하나를 펼친 화면. 배포 환경엔 터미널이 없다는 걸 보여준다

💥 API에서 일부러 에러를 던지고 **사용자 화면 / Vercel 로그**를 나란히.
   사용자에겐 일반 메시지만, 로그엔 전문. 이 비대칭이 정상이다

📸 Lighthouse Before / After 두 장
📸 카톡으로 링크 보냈을 때 미리보기 카드가 뜬 화면

## Day 12–13 — 결제 (별도 프로젝트 필요)

이 앱엔 결제가 없다. 스샷을 얻으려면 `curriculum/week-3.md`대로 들꽃 스토어를 따로 만들어야 한다.
이틀치지만 **교보재가 가장 필요한 구간**이라 권한다.

찍어야 할 것

📸 포트원 콘솔 — 테스트 채널의 `storeId` / `channelKey` / `V2 API Secret` 위치 (**값 가리기**)
📸 결제창이 뜬 화면 — **주소가 우리 도메인이 아닌 것**이 보이게
📸 결제 성공 직후 Atlas 주문 문서가 **아직 `PENDING`인** 화면 ← Day 12의 결정적 관찰
📸 Vercel 로그에 웹훅이 들어와 있는 화면 (내가 부른 적 없는 요청)

💥 **금액 조작** — 이 스터디의 하이라이트
```
36,000원 주문 생성 (DB에 36000 기록)
→ 결제창에는 100원으로
→ 100원 결제
→ /api/payments/complete 호출
```
   서버가 거부하고 `PENDING`으로 남은 화면 / 뚫려서 `PAID`가 된 화면. **둘 다 있으면 최고다**

💥 서명 없이 웹훅 POST → `401`이 오는 화면
