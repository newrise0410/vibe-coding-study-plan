# 자주 막히는 지점

증상 → **원인 구조** → 확인 순서.
답만 적지 않고 왜 그런지를 같이 적었다. 원인 구조를 알면 처음 보는 문제도 풀 수 있다.

---

## 만능 5단계

무슨 문제든 여기서 시작한다.

```
1. F12 → Console          빨간 글씨가 있나? 있으면 전문 복사
2. F12 → Network          상태 코드가 몇인가? Payload에 뭘 보냈나?
3. 터미널 / Vercel Logs    500이면 여기에 진짜 원인이 있다
4. Ctrl+Shift+R           캐시 무시하고 새로 받기
5. 마지막으로 잘 됐던 커밋과 diff 비교
```

**3번을 빠뜨리는 사람이 많다.** 500 에러는 브라우저에 상세가 안 나온다. 서버 쪽을 봐야 한다.
배포 환경에는 터미널이 없으니 **Vercel → 프로젝트 → Logs**.

## 프론트 (Day 1–5)

### CSS를 고쳤는데 안 바뀐다

원인은 넷 중 하나다. **이 순서로** 확인한다.

| 순서 | 확인 | 방법 |
|---|---|---|
| 1 | 선택자가 대상을 찾았나 | Elements → 검사 → Styles에 내 규칙이 **보이기라도 하나** |
| 2 | 다른 규칙에 지고 있나 | Styles 패널의 **취소선** |
| 3 | 그 속성이 그 요소에 먹히나 | `<span>`에 `width` 같은 경우. `display` 확인 |
| 4 | 캐시 | `Ctrl+Shift+R` |

1번에서 아예 안 보이면 선택자 문제다. **점(`.`) 빠뜨림, 오타, 대소문자.**
CSS는 대상을 못 찾아도 에러를 안 낸다. 조용히 무시한다.

### `Cannot read properties of null`

**가장 자주 보는 에러.** "없는 걸 만지려 했다"는 뜻이다.

1. **선택자가 틀림** — 오타, `.`/`#` 빠짐
2. **아직 존재하지 않음** — `<script>`가 `<head>`에 있는 탓에 HTML이 다 읽히기 전에 실행됨

### 모바일에서 글씨가 개미만 하다 / 가로 스크롤이 생긴다

- 글씨 문제 → `<meta name="viewport" ...>` 확인
- 가로 스크롤 → 화면보다 넓은 요소가 있다. 콘솔에:
  ```js
  document.querySelectorAll('*').forEach(el => {
    if (el.getBoundingClientRect().width > document.documentElement.clientWidth)
      el.style.outline = '3px solid red';
  });
  ```

### `'use client'` 관련 에러

| 에러 메시지에 나오는 것 | 원인 |
|---|---|
| `useState`, `useEffect`, `onClick` | 브라우저 기능인데 서버 컴포넌트에 있다 → `'use client'` 추가 |
| `You're importing a component that needs...` | 위와 같음 |
| 반대로 DB·비밀키가 안 읽힘 | `'use client'`가 붙어있다 → 떼야 한다 |

**규칙**: 클릭·상태가 필요하면 클라이언트, DB·비밀키가 필요하면 서버. **둘 다 필요하면 컴포넌트를 나눈다.**

## API / 서버 (Day 6–8)

### 405 Method Not Allowed

함수 이름이 `GET`, `POST`처럼 **대문자**인지 확인. 소문자면 인식 안 된다.

### 500 에러

브라우저에는 상세가 안 나온다. **정상이다.** (에러 상세를 사용자에게 보이면 내부 구조가 샌다)

- 로컬: 터미널을 본다
- 배포: **Vercel → Logs**

### API 응답이 이상하다

Network → 해당 요청 → 탭별로:

| 탭 | 확인 |
|---|---|
| Headers → General | 주소와 방식이 맞나, 상태 코드 |
| **Payload** | **내가 실제로 뭘 보냈나** ← 여기를 안 보고 헤매는 경우가 많다 |
| Response | 서버가 뭘 돌려줬나 |

### 검증을 넣었는데 뚫린다

콘솔에서 직접 `fetch`로 보내 확인한다. **폼을 통하면 브라우저 검증에 걸려서 서버 검증을 시험할 수 없다.**

```js
await fetch('/api/products', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ name: 'x', price: -1 })
}).then(r => r.json().then(d => console.log(r.status, d)));
```

## DB (Day 7)

### 연결이 안 된다 — 로컬부터

| 증상 | 원인 |
|---|---|
| `Authentication failed` | 아이디/비밀번호 틀림. **Atlas 계정 비번이 아니라 DB 사용자 비번**이다 |
| 비밀번호가 맞는데 실패 | 비밀번호에 `@ : / ? # &` 가 있다 → URL 인코딩 필요. **영문+숫자로 재설정이 빠르다** |
| `MONGODB_URI is not defined` | `.env.local` 파일명 확인 (`.env`가 아니다), 서버 재시작 |
| `ECONNREFUSED` / 타임아웃 | Network Access에 `0.0.0.0/0` 있나 |

> **`.env.local`을 고치면 개발 서버를 껐다 켜야 한다.** 자동 반영 안 된다.

### 로컬은 되는데 배포만 안 된다

**이 조합이 압도적 1위다.**

1. **Vercel 환경변수를 안 넣었다** — Settings → Environment Variables. 넣고 **재배포**해야 적용
2. **Atlas Network Access에 `0.0.0.0/0`이 없다** — Vercel 서버 IP는 매번 다르다
3. **파일명 대소문자** — 서버(Linux)는 대소문자를 구분한다

### 커넥션이 계속 늘어난다 / 연결 한도 초과

`lib/mongodb.js`에 `globalThis` 캐시 패턴이 있는지 확인. 개발 중 hot reload 때마다 새로 연결되면 금방 한도를 넘는다.

## 이미지 업로드 (Day 9)

| 증상 | 확인 |
|---|---|
| 업로드가 401/400으로 거부됨 | 서명 파라미터가 실제 업로드 파라미터와 정확히 일치하나 |
| 서명이 만료됨 | 타임스탬프가 오래됐다. 발급받고 바로 써야 한다 |
| 이미지가 화면에 안 뜸 | `next.config.js`에 Cloudinary 도메인 허용했나 |
| `Invalid src prop` | 위와 같음. 에러 메시지에 해결법이 나온다 |
| 큰 파일에서 실패 | 무료 티어 용량 제한 / 업로드 타임아웃 |
| Secret이 브라우저에서 보임 | `NEXT_PUBLIC_`을 잘못 붙였다 → **키 즉시 재발급** |

## 로그인 (Day 10)

| 증상 | 확인 |
|---|---|
| `redirect_uri_mismatch` | 구글 콘솔의 승인된 리디렉션 URI. **localhost와 배포 주소 둘 다** 등록했나. 끝 슬래시까지 정확히 |
| 로그인은 되는데 바로 풀림 | `AUTH_SECRET` 없음 / `AUTH_URL`이 실제 주소와 다름 |
| 배포에서만 로그인 실패 | Vercel 환경변수 누락. `AUTH_URL`을 배포 주소로 |
| 로그인했는데 관리자 기능이 안 됨 | Atlas에서 내 사용자 문서의 `role`이 `admin`인가 |
| 로그아웃해도 화면이 그대로 | 캐시. `Ctrl+Shift+R` |
| **로그아웃 상태로 API가 뚫림** | **화면에서만 막고 API에서 안 막았다.** 심각. Day 10 부숴보기 C 참조 |

## 결제 (Day 12–13)

| 증상 | 확인 |
|---|---|
| 결제창이 안 뜬다 | storeId·channelKey 오타 / `NEXT_PUBLIC_` 누락 / SDK 버전 |
| SDK 함수가 없다고 나옴 | 버전이 다르다. **포트원 공식 문서 내용을 복사해 AI에게 주는 게 가장 빠르다** |
| 결제는 됐는데 주문이 PENDING | 서버 검증(`/complete`)이 호출 안 됨. Network 확인 |
| 서버 조회가 401 | `PORTONE_API_SECRET` / `Authorization: PortOne {secret}` 형식 |
| 금액 불일치로 거부됨 | **정상 동작일 수 있다.** DB 주문 금액과 결제 금액을 직접 비교 |
| 웹훅이 안 온다 | 콘솔에 URL 등록했나 / **배포 주소**인가 (localhost엔 안 온다) / 발송 이력 확인 |
| 웹훅이 계속 재시도됨 | 200을 안 돌려주고 있다 |
| 같은 주문이 두 번 처리됨 | 멱등 처리 없음 |
| **결제 없이도 주문이 PAID가 됨** | 서버 검증이 없거나 형식적이다. 심각. Day 13 부숴보기 B |

## Git / 배포

### 푸시했는데 사이트가 그대로다

1. GitHub에서 **파일이 실제로 바뀌었나** (푸시가 됐나)
2. Vercel → Deployments → 배포가 돌았나, **실패했나**
3. 실패했으면 로그의 마지막 에러 줄을 복사 → AI에게
4. 전부 정상인데 안 바뀌면 → 캐시. `Ctrl+Shift+R`

### 빌드가 실패한다

로컬에서 먼저 확인한다:

```bash
npm run build
```

`npm run dev`는 통과하는데 `build`에서 터지는 경우가 흔하다. 배포 전에 이걸 돌려보는 습관이 시간을 아낀다.

### 실수로 뭔가 망가뜨렸다

| 상황 | 방법 |
|---|---|
| 커밋 전 | Orca Source Control 패널에서 파일 우클릭 → **discard** |
| 커밋 후, 푸시 전 | AI에게: "직전 커밋을 취소하고 싶어" |
| 푸시까지 함 | GitHub → Commits → 잘 되던 커밋에서 내용 복사 |

**커밋을 자주 하면 이 표를 볼 일이 없다.** 잘 되는 상태가 되면 즉시 커밋한다.

### `.env.local`을 커밋해버렸다

1. **모든 키를 즉시 재발급한다** (Atlas 비번 변경, Cloudinary·포트원·구글 키 재발급)
2. `.gitignore`에 추가하고 파일을 추적에서 제거
3. **파일에서 지우는 것만으로는 부족하다.** Git 히스토리에 남아 있다

## AI 관련

### AI가 시키지도 않은 걸 바꿨다

- **diff를 먼저 본다** — Orca diff 뷰어에서 **거터의 AI 마커**를 보면 어디를 에이전트가 썼는지 바로 보인다
- `"이 줄은 왜 지웠어? 원래대로 되돌려줘"`
- 재발 방지: 요청할 때 **범위를 못 박는다**

### AI가 만든 결제/인증 코드가 미심쩍다

**그 감이 맞을 확률이 높다.** 이 영역은 AI가 가장 자주 빠뜨린다.

```
이 코드에서 다음을 확인해줘:
1. 금액을 클라이언트에서 받고 있는 곳이 있나
2. 권한 검사가 API 안에서 이뤄지나, 화면에서만 하나
3. 웹훅 서명 검증과 멱등 처리가 있나
고치지 말고 목록만 먼저 알려줘.
```

그리고 **직접 뚫어본다.** 콘솔에서 `fetch`로 공격해보는 게 가장 확실하다.

### AI가 최신 SDK를 모른다

결제 SDK에서 특히 그렇다. **공식 문서 페이지 내용을 복사해서 같이 주면** 정확도가 크게 오른다.
이것도 배울 점이다 — AI가 모르는 최신 정보는 내가 물어다 줘야 한다.

